# VoiceChat 0.0.14

⌘Q no longer quits VoiceChat by accident.

## What's new

- **⌘Q closes the window, not the app.** With a VoiceChat window in front, ⌘Q now closes that window, the same as its close button. A live conversation closed this way ends, as it always has when you close its window. VoiceChat itself stays in the menu bar, ready for the next conversation.
  - To quit VoiceChat, use **Quit VoiceChat** in its menu bar menu. That's now the only way to quit it.
  - [Talking Head 0.0.12](https://github.com/sandipchitale/TalkingHead/releases/tag/v0.0.12) makes the same change, so ⌘Q on its face window no longer quits it either.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again. It applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new app.

## Install

New here? VoiceChat requires **macOS 26 (Tahoe)** or later, and one download runs on both Apple silicon and Intel.

1. Download `VoiceChat-0.0.14.zip`, unzip it, and move `VoiceChat.app` to `/Applications`.
2. Run the `xattr` command above.
3. Optionally, check the download with `shasum -a 256 -c VoiceChat-0.0.14.zip.sha256`.
4. Open **MCP Server Config…** from the menu bar and copy the line for your MCP host.

The [0.0.6 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.6) explain debate mode, the [0.0.9 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.9) the Talking Head integration, and the [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover the full feature list.

## Known issues

- **In Talking Head mode, follow along in Talking Head's speech bubble.** Click the face to open it. It highlights each word as it's spoken. VoiceChat's reply pane doesn't highlight in this mode.
- **A debate needs two separate MCP clients.** One client holds one conversation at a time, so two subagents of the same session can't take both seats. Use a second app, or a second `claude -p` process.
- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **The MCP Server (HTTP) is experimental and off by default**, and has to be switched on from the menu bar after each launch, unless `VOICECHAT_MCP_HTTP_PORT` is set. A local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds, but Claude Code moves a tool call to the background after 120 seconds. The conversation still continues when you send. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **No settings screen yet.** There's no choice of speech voice or rate outside a debate, and no vocabulary editing from the UI.
- **English only.**

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
