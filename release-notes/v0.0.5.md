# VoiceChat 0.0.5

The window now shows which folders the conversation is about, straight from the host.

## What's new

- **Workspace roots in the bottom bar.** When the MCP host supports roots, VoiceChat asks it for them (`roots/list`) and shows a folder chip beside *Connected to…* with the number of roots. Clicking it lists each root's name and path, with a **Reveal** link that opens the folder in the Finder. The list refreshes when the host says its roots changed. Hosts that report no roots, or don't support them, show no chip.
- **Streamable HTTP connections can show the project too.** The HTTP transport has no working directory of its own, so it previously showed nothing about the project. Roots fill that gap for hosts that supply them.

Roots are fetched off the conversation's path and abandoned after five seconds, so a host that is slow to answer — or never answers — cannot delay a turn.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.5.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.5.zip.sha256`. The [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list, and the README covers building from source. The [0.0.4 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.4) cover the pane layout and divider added in that release.

## Known issues

- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default.** It has sometimes answered a fresh conversation with "ended" immediately and never opened a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds for you to speak, but Claude Code moves a tool call to the background after 120 seconds. The conversation still continues when you send, just through a background notification. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **No settings screen yet** — no choice of speech voice or rate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
