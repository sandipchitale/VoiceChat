# VoiceChat 0.0.4

A layout release: you can now arrange and size the two panes yourself, and the answer you're replying to stays on screen.

## What's new

- **Side-by-side or stacked panes.** A new button in the header, beside the pin (or ⌥⌘L), switches between the prompt and response side by side and the prompt stacked above the response. Its icon shows the layout a click switches to.
- **A draggable divider between the panes.** Drag it to give either pane more room; double-click it to split the space evenly again. It stops each pane at a usable minimum. The layout, and a separate proportion for each layout, are remembered across launches and shared by every conversation window.
- **The previous answer stays visible while you reply.** Starting the next turn used to clear both panes, so the answer you were responding to disappeared. The prompt pane still clears, but the response stays up, dimmed and read-only and labelled *Previous response*, until the next answer arrives. History and export are unchanged.
- **Clearer empty response pane.** It used to say "Type text here or wait for a response…", which invited typing that went nowhere. It now reads *The response will appear here.*, or *Waiting for the response…* after you send, and the pane is editable only once a response has arrived.
- **Tooltips on every header control.** The opacity slider and its end icons now have their own tooltips (the slider's shows the current percentage), and the theme buttons say what each one does. Tooltips appear only while VoiceChat is the frontmost app.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.4.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.4.zip.sha256`. The [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list, and the README covers building from source.

## Known issues

- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default.** It has sometimes answered a fresh conversation with "ended" immediately and never opened a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds for you to speak, but Claude Code moves a tool call to the background after 120 seconds. The conversation still continues when you send, just through a background notification. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **The project isn't shown for Streamable HTTP connections**, only for stdio ones, because the HTTP path doesn't yet learn the host's working directory.
- **No settings screen yet** — no choice of speech voice or rate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
