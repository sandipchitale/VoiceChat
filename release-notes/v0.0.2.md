# VoiceChat 0.0.2

A small release: one new feature.

## What's new

- **Mute button.** Read replies silently without turning your Mac's volume down. The speaker button at the bottom left of the response pane (or **⇧⌘M**) mutes the reading; it shows red with a slash while muted. Muting only silences the sound — the sentence highlighting, the timing and the automatic move to the next turn all carry on, so a muted reply never stalls or skips a turn. You can toggle it mid-reply: the sentence being read starts over, silently or out loud. The setting is remembered and shared by every conversation window.

## Upgrading from 0.0.1

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart any MCP host connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.2.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.2.zip.sha256`. The [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list, and the README covers building from source.

## Known issues

Unchanged from 0.0.1:

- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default.** It sometimes answers a fresh conversation with "ended" immediately and never opens a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **No settings screen yet** — no choice of speech voice or rate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
