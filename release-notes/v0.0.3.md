# VoiceChat 0.0.3

A small release: the window now shows which app and model you're talking to.

## What's new

- **Host and model in the header.** A chip at the top of the conversation window shows the app driving the conversation and, if it says, the model — for example `claude-opus-5 · Claude Code`. The app name comes from the MCP host itself (the name it gives when it connects), so it appears even if the model doesn't mention it. Claude Code shows as **Claude Code** and Claude Desktop as **Claude Desktop**; other hosts appear under the name they report. The bottom bar reads `Connected to <host> — <project> · <model>`, and the menu bar lists each conversation by host and project.
- **`converse` takes an optional `model` argument.** The tool description asks the model to pass its own name; if it doesn't, the chip just shows the host.
- **Window title shows the project.** It now reads `VoiceChat 0.0.3 — <project>` (the folder the host is working in), since the host moved into the chip.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.3.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.3.zip.sha256`. The [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list, and the README covers building from source.

## Known issues

Unchanged from 0.0.2:

- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default.** It has sometimes answered a fresh conversation with "ended" immediately and never opened a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **No settings screen yet** — no choice of speech voice or rate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
