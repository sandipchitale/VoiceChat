# VoiceChat 0.0.1

The first public release. VoiceChat lets you hold a spoken, multi-turn conversation with whatever LLM is driving your [MCP](https://modelcontextprotocol.io) host — Claude Code, an IDE, an agent — in a native macOS window, without typing and without watching the host's own chat surface. The model calls one tool, `converse`; a window opens; you speak or type; the reply is read aloud; the loop continues until you end it.

This is an early release. It works, but it has rough edges — see **Known issues** before you rely on it.

## Install

Requires **macOS 26 (Tahoe)** or later. One download runs on both Apple silicon and Intel Macs.

1. Download `VoiceChat-0.0.1.zip` below, unzip it, and move `VoiceChat.app` to `/Applications`.
2. **The app is not signed with an Apple Developer ID and is not notarised**, so macOS will say it is "damaged" or "cannot be verified". It isn't damaged — clear the quarantine flag your browser added, then open it:

   ```bash
   xattr -dr com.apple.quarantine /Applications/VoiceChat.app
   ```
3. Optionally check the download: `shasum -a 256 -c VoiceChat-0.0.1.zip.sha256`.

Don't want to run an unsigned binary? Build it from source instead — see the README. A copy you build yourself is never quarantined.

## Connect an MCP host

Register the stdio server that ships inside the app, for example in `.mcp.json`:

```json
{
  "mcpServers": {
    "voicechat-stdio": {
      "type": "stdio",
      "command": "/Applications/VoiceChat.app/Contents/MacOS/voicechat-mcp"
    }
  }
}
```

It launches VoiceChat for you if it isn't already running. The menu bar's **MCP Server Config…** item shows a ready-to-copy snippet. To try VoiceChat with no host at all, choose **Test Conversation…** from the menu bar icon.

The first time you dictate, macOS asks for **Microphone** and **Speech Recognition** access, and may need to download its on-device speech model for your language.

## What's in it

- **Spoken conversations over MCP.** A single `converse` tool; long waits are handled without timing out the host.
- **Dictation and voice commands.** Speech recognition runs on-device (Apple's `SpeechAnalyzer`). A command mode covers about 150 documented phrases — select, move, edit, delete, and format text (bold, italic, underline, case) by voice, at character, word, sentence, paragraph and line granularity.
- **Replies read aloud** with sentence-by-sentence highlighting. The microphone is fully off while it speaks, so the app never transcribes its own voice.
- **A native window:** frameless glass with light, dark and system themes, an opacity slider, and a pin to keep it above other windows or not.
- **History.** Earlier turns stay in a strip; load one, edit the prompt, and send it as a new turn. Export the conversation as Markdown.
- **Two ways to connect:** the stdio server above, and an optional **Streamable HTTP** transport (below).
- **Everything stays on your Mac.** No audio or transcript is sent anywhere by VoiceChat.

## Known issues

- **Not signed or notarised** (see Install). Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after you install an update.
- **Streamable HTTP is experimental and off by default.** Turn it on from the menu bar (**Streamable HTTP**, port 8765), then register `http://localhost:8765/mcp` as a `streamable-http` server. Two caveats: it sometimes answers a fresh conversation with "ended" immediately and never opens a window (cause not yet found — the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine, unlike the stdio path.
- **No settings screen yet.** You can't choose the speech voice or rate, or edit your custom vocabulary, from the UI.
- **Sparse menu bar and logging.** No permission status, no launch-at-login, no log viewer.
- **English only.** Speech recognition is set up for US English, and the command vocabulary is English.
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. If you hit one, a report with the crash log from `~/Library/Logs/DiagnosticReports` would help a lot.

Bug reports and feedback are welcome on the [issue tracker](../../issues).
