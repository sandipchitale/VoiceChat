# VoiceChat 0.0.6

Two AIs, one motion: VoiceChat can now host a debate between two MCP clients and let you moderate it.

## What's new

- **Debate rooms.** Menu bar → **New Debate…** (⌥⌘D): set the motion, what each side argues, how many statements before closing arguments, and a voice per side. The room gets a short id like `owl-42`.
- **Any MCP client can take a seat.** The menu offers **Copy join instruction** per free seat; paste that sentence into whichever client should argue it. Because each debater is a separate MCP client, the two sides can be different apps and different models — Claude Code against Gemini, say. `converse` gained two optional arguments, `debate_id` and `side`, passed on the first call only.
- **You pass each statement across.** When a statement has been read out, it appears in the other window's prompt pane and waits for **Send**. Edit it first to interject — anything you add is marked `> Moderator:`, and each side is briefed to comply with those lines.
- **A debate bar in each window** shows the motion, the seat, the statement count and what it is waiting for, plus **Skip turn** (when a debater goes quiet) and **End debate**. Closing either window ends both sides, and after the statement budget each side gives a closing statement.
- **Told apart by ear and eye.** Each seat speaks in its own voice (falling back to distinct pitch and rate if your Mac has only one installed), each debater names itself in its first sentence, and the two windows are placed side by side — stacked top and bottom on a screen too narrow for both.
- **Muting still works the way you would want.** Silence both windows and the debate runs on unchanged: same pacing, same sentence highlight, so you can follow the argument by eye.

Debate windows open with the microphone off, since their turns arrive as text.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.6.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.6.zip.sha256`. The [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list, and the README covers building from source.

## Known issues

- **A debate needs two separate MCP clients.** One client holds one conversation at a time, so two subagents of the same session cannot take both seats — use a second app, or a second `claude -p` process.
- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default.** It has sometimes answered a fresh conversation with "ended" immediately and never opened a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds, but Claude Code moves a tool call to the background after 120 seconds. The conversation continues when you send, just through a background notification. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **The project isn't shown for Streamable HTTP connections** unless the host reports MCP roots, because the HTTP path has no working directory of its own.
- **No settings screen yet** — no choice of speech voice or rate outside a debate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
