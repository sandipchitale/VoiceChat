# VoiceChat 0.0.9

Replies can now be read by an animated talking head.

## What's new

- **Optional Talking Head integration.** If [Talking Head](https://github.com/sandipchitale/TalkingHead) and its `th` command are installed, a person icon appears next to the speaker button under the reply pane. Turn it on, and replies are read by Talking Head's lip-syncing face instead of VoiceChat's own voice. The conversation waits until Talking Head finishes before moving to the next turn.
  - The same cleaned-up text the built-in voice reads is sent, without Markdown symbols and with code blocks handled. If you've selected part of a reply, only that part is sent.
  - The Talking Head window stays on top of other windows while it speaks.
  - **Stop** closes it immediately. So does **Mute**: muted means silent, so Talking Head isn't started while muted.
  - The setting is shared by every conversation window and remembered.
  - Without `th` installed, nothing changes and the button isn't shown.

VoiceChat looks for `th` in `~/.local/bin`, `/usr/local/bin`, `/opt/homebrew/bin` and inside `/Applications/TalkingHead.app`, and only uses one that points into `TalkingHead.app`.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again. It applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? VoiceChat requires **macOS 26 (Tahoe)** or later, and one download runs on both Apple silicon and Intel.

1. Download `VoiceChat-0.0.9.zip`, unzip it, and move `VoiceChat.app` to `/Applications`.
2. Run the `xattr` command above.
3. Optionally, check the download with `shasum -a 256 -c VoiceChat-0.0.9.zip.sha256`.
4. Open **MCP Server Config…** from the menu bar and copy the line for your MCP host.

The [0.0.6 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.6) explain debate mode, and the [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover the full feature list.

## Known issues

- **No sentence highlighting in Talking Head mode.** Talking Head doesn't report its progress, so VoiceChat can't highlight the sentence being read. Talking Head's own speech bubble highlights each word instead.
- **A debate needs two separate MCP clients.** One client holds one conversation at a time, so two subagents of the same session can't take both seats. Use a second app, or a second `claude -p` process.
- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default**, and has to be switched on from the menu bar after each launch. A local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds, but Claude Code moves a tool call to the background after 120 seconds. The conversation still continues when you send. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **No settings screen yet.** There's no choice of speech voice or rate outside a debate, and no vocabulary editing from the UI.
- **English only.**

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
