# VoiceChat 0.0.16

New Debate can now start the AI for each side itself, and set each side's Talking Head face.

## What's new

- **A debater for each side.** In **New Debate…**, each side has a **Debater** choice: **None**, or **Claude Code** (`claude -p`), **Antigravity** (`agy -p`) or **Codex** (`codex exec`), whichever of those commands are on your PATH.
  - Choosing one proposes the command to run, in a box you can edit. **Reset** brings the proposal back. It runs in your shell, with this side's join instruction in `$VOICECHAT_JOIN`, so it keeps working if you change the motion afterwards.
  - Each debater runs in `~/Library/Application Support/VoiceChat/debates/<id>/`, with its output logged there, and is stopped when the debate ends or VoiceChat quits. If one exits without taking its seat, VoiceChat tells you and points to its log.
  - Claude Code and Codex are given VoiceChat's own server on the command line, so their MCP settings don't matter, and Claude Code may call only `converse`. Antigravity uses its own MCP settings (add VoiceChat there first) and runs with `--dangerously-skip-permissions`, since nobody can answer a permission prompt in print mode. Each CLI must be logged in.
- **None shows the prompt to paste.** For a side set to None, the same box shows its join instruction, updating as you type the motion, with a **Copy** button. The debate's id is chosen when the dialog opens, so a prompt you copy early is already right.
- **A face for each side.** With Talking Head installed, each side has a **Face** choice: Man or Woman. Picking one side's face gives the other side the other face, so the two never share a window ([Talking Head 0.0.13](https://github.com/sandipchitale/TalkingHead/releases/tag/v0.0.13) or later shows them side by side).

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again. It applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new app.

## Install

New here? VoiceChat requires **macOS 26 (Tahoe)** or later, and one download runs on both Apple silicon and Intel.

1. Download `VoiceChat-0.0.16.zip`, unzip it, and move `VoiceChat.app` to `/Applications`.
2. Run the `xattr` command above.
3. Optionally, check the download with `shasum -a 256 -c VoiceChat-0.0.16.zip.sha256`.
4. Open **MCP Server Config…** from the menu bar and copy the line for your MCP host.

The [0.0.6 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.6) explain debate mode, the [0.0.9 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.9) the Talking Head integration, and the [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover the full feature list.

## Known issues

- **In Talking Head mode, follow along in Talking Head's speech bubble.** Click the face to open it. It highlights each word as it's spoken. VoiceChat's reply pane doesn't highlight in this mode.
- **A debate needs two separate MCP clients.** One client holds one conversation at a time, so two subagents of the same session can't take both seats. Use a second app, or a second `claude -p` process.
- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **The MCP Server (HTTP) is experimental and off by default**, and has to be switched on from the menu bar after each launch, unless `VOICECHAT_MCP_HTTP_PORT` is set. A local HTTP port is reachable by any user account on the machine. A `converse` call over HTTP has been seen to wait past its 240-second limit without answering, so Claude Code gave up on it; the stdio server doesn't have this problem.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds, but Claude Code moves a tool call to the background after 120 seconds. The conversation still continues when you send. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **No settings screen yet.** There's no choice of speech voice or rate outside a debate, and no vocabulary editing from the UI.
- **Codex debaters are untested.** The Codex command follows Codex's documentation, but couldn't be run end to end before this release. If it stalls waiting for approval, add `--approve-for-me` to its command in the dialog.
- **English only.**

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
