# VoiceChat 0.0.7

Debate mode, made pleasant: normal voices, an automatic handover, and a setup window that looks like the rest of the app.

![A debate in progress: Claude Code for the motion, Gemini against](https://raw.githubusercontent.com/sandipchitale/VoiceChat/main/screenshots/debate.png)

## What's new

- **Both sides speak normally.** 0.0.6 chose a voice for each seat from the installed list, which on macOS starts with the novelty voices — Albert, Bad News, Bubbles — so debates sounded ridiculous. Both seats now use your Mac's standard voice unless you pick one, separated only by a slight difference in pitch and rate. The picker no longer offers the novelty voices at all.
- **Auto handover, per window.** Each debate bar has an **Auto** switch, off by default. While it is on, a statement arriving in that window goes to its debater without you pressing Send — and switching it on passes along one already waiting. Turn it on in one window to moderate a single side, or in both to let the debate run itself.
- **A rebuilt New Debate window.** It is now made of the app's own glass: the motion spans the top as a multi-line field, the two seats sit side by side as mirrored cards with their own voice menus, and house rules share a row with a proper minus/plus statement counter. The previous version used a stock grouped form, which right-aligned every control and squeezed the motion into a single line.

## Upgrading from an earlier version

Quit VoiceChat (menu bar icon → **Quit VoiceChat**), replace `/Applications/VoiceChat.app` with the new one, and clear the quarantine flag again — it applies to each download:

```bash
xattr -dr com.apple.quarantine /Applications/VoiceChat.app
```

macOS may ask for Microphone and Speech Recognition access again, because the app is ad-hoc signed and each build looks new to it. Restart your MCP host's connection (for Claude Code, `/mcp`) so it reconnects to the new daemon.

## Install

New here? Requires **macOS 26 (Tahoe)** or later; one download runs on Apple silicon and Intel. Download `VoiceChat-0.0.7.zip`, unzip it, move `VoiceChat.app` to `/Applications`, and run the `xattr` command above. Check the download with `shasum -a 256 -c VoiceChat-0.0.7.zip.sha256`. The [0.0.6 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.6) explain debate mode, and the [0.0.1 notes](https://github.com/sandipchitale/VoiceChat/releases/tag/v0.0.1) cover connecting an MCP host and the full feature list.

## Known issues

- **A debate needs two separate MCP clients.** One client holds one conversation at a time, so two subagents of the same session cannot take both seats — use a second app, or a second `claude -p` process.
- **Not signed or notarised**, hence the `xattr` step. Because it is only ad-hoc signed, macOS may ask for microphone and speech access again after each update.
- **Streamable HTTP is experimental and off by default**, and has to be switched on from the menu bar after each launch. It has sometimes answered a fresh conversation with "ended" immediately and never opened a window (cause not yet found; the stdio server doesn't do this), and a local HTTP port is reachable by any user account on the machine.
- **Long waits get backgrounded in Claude Code.** A `converse` call waits up to 240 seconds, but Claude Code moves a tool call to the background after 120 seconds. The conversation continues when you send, just through a background notification. For the stdio server, adding `"env": { "VOICECHAT_TURN_WAIT_MS": "60000" }` to its entry in your MCP configuration avoids it.
- **The project isn't shown for Streamable HTTP connections** unless the host reports MCP roots, because the HTTP path has no working directory of its own.
- **No settings screen yet** — no choice of speech voice or rate outside a debate, and no vocabulary editing from the UI.
- **Sparse menu bar and logging** — no permission status, launch-at-login or log viewer.
- **English only.**
- **One unexplained crash** inside SwiftUI's rendering was seen once during development and has not reproduced. A report with the crash log from `~/Library/Logs/DiagnosticReports` would help.

Bug reports and feedback are welcome on the [issue tracker](https://github.com/sandipchitale/VoiceChat/issues).
